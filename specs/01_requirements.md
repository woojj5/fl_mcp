# FL Platform 요구사항 기획서

## 1. 배경과 목표

분산된 데이터셋을 한곳에 합치지 않고 협력 학습할 수 있는 연합학습 실험 환경을 제공한다. 개발자는 별도 프로세스/컨테이너로 구성한 서버·클라이언트 배포를 실행하고, 학습 결과를 대시보드 및 SQLite 기록으로 확인할 수 있어야 한다.

## 2. 대상 사용자

- 연합학습 알고리즘과 모델을 실험하는 연구자·개발자
- 여러 노드의 학습을 시연·운영하고 진행 상황을 확인하는 운영자
- 로컬 데이터를 외부로 옮기지 않고 학습에 참여하는 클라이언트 운영자

## 3. 제품 범위

### 포함 범위

1. 대시보드 모드에서 학습 기록과 분산 노드 상태 조회
2. 대시보드에서 PyTorch 기반 단일 머신 연합학습 시뮬레이션 시작
3. 분산 서버의 클라이언트 등록, 모델 배포, 가중치 수신·집계 및 예측 API
4. 클라이언트의 자동/수동 학습, 상태 조회, 로컬 예측 및 사용자 데이터 업로드
5. YAML 기반 실험 설정과 명령행 옵션 기반 서버·클라이언트 설정
6. Bearer token/Basic 인증, HTTPS 전송 암호화 및 Docker Compose 배포
7. 지원 데이터 분할·집계 전략·학습 파라미터 선택

### 제외 또는 확인 불가 범위

- 운영 환경의 고가용성, 장애 복구 및 확장 정책
- 운영 환경의 모델·데이터 수명주기와 성능 보장
- 스킬에서 주장하는 React Native 앱 생성, Jest/ESLint 검사 및 마이크로서비스 경계 검사: 이 저장소의 애플리케이션 코드와 맞지 않음

## 4. 기능 요구사항

| ID | 요구사항 | 우선순위 | 인수 조건 |
|---|---|---:|---|
| FR-01 | 인자 없이 실행하거나 `dashboard`를 지정해 대시보드를 실행한다. | P0 | 호스트·포트·SQLite 경로를 지정할 수 있고, 기본 포트는 5000이다. |
| FR-02 | 대시보드는 SQLite 학습 기록과 분산 노드 상태를 표시한다. | P0 | `/`는 기록을, `/deployment`는 지정한 FL 서버·클라이언트 상태를 표시한다. |
| FR-03 | 대시보드에서 로컬 시뮬레이션을 실행한다. | P0 | 데이터셋·모델·라운드·클라이언트 수·분할·전략을 선택하고 진행 상태와 결과를 기록한다. |
| FR-04 | 서버는 등록된 클라이언트와 최소 인원 조건을 바탕으로 학습 라운드를 진행한다. | P0 | 최소 클라이언트, 라운드 수, 라운드 참여 수, 모델, 데이터셋, 전략을 설정할 수 있다. |
| FR-05 | 서버는 상태·등록·전역 모델·가중치 업로드·예측·관리 API를 제공한다. | P0 | API 요청에는 유효한 Bearer token이 필요하다. |
| FR-06 | 클라이언트는 서버에 등록하고 로컬 데이터로 학습한 뒤 결과를 업로드한다. | P0 | 클라이언트 ID, HTTPS 서버 URL, 데이터 분할, 학습 파라미터를 설정하고 자동/수동 시작을 선택한다. |
| FR-07 | 클라이언트는 상태·수동 학습·로컬 예측·사용자 데이터 업로드·자동 학습 제어 API를 제공한다. | P0 | ZIP/NPZ/CSV 업로드가 해당 노드의 다음 학습에 사용된다. |
| FR-08 | 서버는 라운드와 클라이언트 업데이트 지표를 SQLite에 저장한다. | P1 | DB 경로를 지정할 수 있으며 대시보드 기본값은 `./tracking.db`, 서버 기본값은 `./server_tracking.db`다. |
| FR-09 | 런타임 서비스는 인증과 HTTPS를 사용한다. | P0 | server/client API는 Bearer token, 대시보드는 Basic 인증을 적용하고, 서비스 시작 시 TLS 인증서가 필요하다. |
| FR-10 | Docker Compose로 서버, 복수 클라이언트, 대시보드를 함께 실행한다. | P1 | 기본 구성은 서버 1개, 클라이언트 2개, 대시보드 1개이며 인증·TLS 설정이 필수다. |

## 5. 비기능 요구사항

- **데이터 지역성:** 학습 원본은 클라이언트에 두고 모델 가중치/업데이트만 서버와 교환한다. 사용자 데이터 업로드는 대상 클라이언트로 직접 전송한다.
- **설정 재현성:** seed, 모델, 데이터셋, 분할 방식, 최적화 설정을 기록할 수 있어야 한다.
- **운영 가시성:** 서버·클라이언트 상태와 라운드/학습 결과를 조회할 수 있어야 한다.
- **배포 단순성:** Docker Compose 및 개별 Python 진입점으로 시작할 수 있어야 한다.
- **보안:** API 인증, TLS 인증서 검증, 파일 크기 제한을 제공한다. 비밀정보 회전, 신뢰 CA, 네트워크 정책과 production 보안 검토는 별도 운영 책임이다.

## 6. 주요 사용자 시나리오

### 로컬 시뮬레이션

1. 운영자가 대시보드에 Basic 인증으로 로그인한다.
2. 홈 화면에서 데이터셋, 모델, 라운드, 분할 및 전략을 지정해 시뮬레이션을 시작한다.
3. 백그라운드 학습 진행 상태와 라운드별 지표를 확인한다.
4. 완료된 결과는 SQLite에 기록된다.

### 분산 학습

1. 서버를 모델·데이터셋·전략 및 라운드 설정과 함께 실행한다.
2. 각 클라이언트를 고유 ID, 파티션 ID, 분할 방식으로 실행한다.
3. 클라이언트가 등록하고 서버의 전역 모델을 받아 로컬 학습을 수행한다.
4. 학습 업데이트를 업로드하고 서버가 라운드 결과를 집계한다.
5. 대시보드 및 상태 API로 진행 상황을 확인한다.

## 7. 성공 지표와 검증 기준

- 설정한 최소 클라이언트 수가 모이면 라운드가 시작된다.
- 클라이언트 로컬 데이터 학습이 완료되고 서버에서 집계 결과를 확인할 수 있다.
- 서버와 클라이언트의 상태·관리 API가 정상 응답한다.
- 추적 DB에 학습 이력이 남고 대시보드가 이를 표시한다.
- 재현에 필요한 핵심 설정과 seed를 기록한다.

현재 시뮬레이션과 사용자 데이터 업로드는 로컬/데모 목적이다. 인증·TLS 운영은 인증서 및 비밀정보 구성을 전제로 하며 production 배포 검토를 대체하지 않는다.
